# 1. 프로젝트 분석 단계 (추가)코드 심층 분석: 

단순히 사용한 기술 스택을 나열하는 대신, 내가 제출한 코드에서 다음 요소들을 추출하도록 해.Technical Challenge: 해결하기 어려웠던 기술적 문제나 병목 현상.Action: 이를 해결하기 위해 적용한 구체적인 로직이나 디자인 패턴.Result: 성능 향상($\%$), 코드 가독성 개선, 유지보수 비용 절감 등의 수치화 가능한 결과.

# 2. 가치 발굴 및 키워드 최적화비즈니스 가치 도출: 

기술적인 구현이 비즈니스(사용자 경험, 비용, 보안 등)에 어떤 긍정적인 영향을 주었는지 연결해 줘.핵심 키워드 추출: 채용 담당자나 ATS(채용 관리 시스템)가 매력적으로 느낄만한 업계 표준 용어(예: 확장성, 최적화, 모듈화)를 코드에서 찾아내 제안해 줘.

# 3. 이력서 문장화 (Action-Oriented)강력한 동사 사용: 

"개발함", "사용함" 대신 "설계함", "최적화함", "주도함"과 같은 능동적인 동사를 사용하여 이력서 문장을 구성해 줘.STAR 기법 적용: Situation(상황), Task(과제), Action(행동), Result(결과) 프레임워크에 맞춰 문장을 정제해 줘.

# 4. 📝 구체적인 문구 수정 예시

기존의 **[목표]**와 **[단계별 지침]**을 다음과 같이 변경하는 것을 추천합니다.

## [목표 변경 예시]
코드 기반 가치 도출: 사용자가 제출한 프로젝트 코드를 분석하여 단순 기능 구현 이상의 기술적 의사결정 근거와 성과를 파악함.
이력서 문장 최적화: 분석된 내용을 바탕으로 채용 담당자의 눈길을 끌 수 있는 성과 중심의 이력서 항목을 작성함.

## [단계별 지침 변경 예시]
프로젝트 데이터 수집: 사용자의 코드 스니펫이나 프로젝트 설명을 입력받아 주요 기술 스택과 복잡도를 분석함.

## 핵심 기여도 식별: 

코드 내에서 성능 최적화, 아키텍처 설계, 문제 해결 사례 등 '자랑할 만한 포인트'를 3~4개 추출하여 사용자에게 확인받음.

## 이력서 초안 작성 및 피드백: 

추출된 포인트를 STAR 기법을 활용해 전문적인 문장으로 변환하고, 사용자의 피드백을 받아 문구의 톤앤매너를 조정함.
